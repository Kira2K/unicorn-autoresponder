# AppDb: SQL вместо Noco

При `APP_DB=postgres` четыре прежних Noco-чтения AppDb используют PostgreSQL:
список учеников для HH, ученик по имени, HH-аккаунт по имени и по ID чата.
Правила выбора ученика, Ru/En, стека, стоп-листов и ошибок сохранены.

Telegram-записи и список клиентов для проверки прокси по-прежнему читаются
из Google Sheets. Их отсутствие в Noco не считается ошибкой переноса.

## Файлы

- `postgres-db.mts` — собирает четыре SQL-чтения и два прежних чтения Sheets.
- `record-source.mts`, `record-relations.mts` — текущие записи и связи.
- `record-order.mts` — прежний порядок: `nc_order`, затем числовой ID.
- `pages.mts` — чтение всех страниц без пропусков.
- `runtime.mts`, `config.mts` — подключение по `APP_DB_POSTGRES_*`.
- `hh-readiness.mts` — данные SQL для проверки готовности HH.

AppDb только читает. При ошибке SQL не подставляет другую базу.
`APP_DB=noco` и выбор Sheets по умолчанию сохраняют прежнее поведение.
HH Profile Filler и проверка готовности HH выбирают SQL только явно;
в остальных режимах их прежний источник Noco не меняется.

Ежедневный скрипт откликов сохраняет явный `APP_DB=postgres`.
Отдельные задания планировщика и пути к другим копиям проекта автоматически
не переключаются — их нужно проверить на машине запуска.

## Запуск и проверка

[Инструкция для другой машины](../../../../docs/SQL_START.md).
Node 24.20.0: `npm run db:postgres:test`, `npm run db:noco:test`,
`npm run noco:core:test`, `npm run typecheck`.
Тесты сравнивают старые и новые результаты без браузеров и внешних отправок.
