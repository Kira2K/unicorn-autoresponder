# PostgreSQL-клиент

Приложение читает и меняет текущие SQL-колонки через `working-client.mts`.
Архивный `client.mts` сохранён для проверки старой выгрузки; он не служит
источником текущих данных приложения.

Общий запуск описан в [SQL_START.md](../../../docs/SQL_START.md).
Подключение передаётся снаружи. Клиент не читает ENV и не меняет схему при старте.

## Методы рабочего клиента

- `listTables`, `getRecord`, `listRecords`, `findRecords` — таблицы и записи.
- `listRelated` — связанные записи из текущих ключей и таблиц связей.
- `createRecord`, `patchRecord`, `deleteRecord` — создание, изменение, удаление.
- `linkRecord`, `unlinkRecord` — привязка и отвязка.
- `transaction` — несколько изменений одной операцией: все сохранятся либо все отменятся.

По умолчанию запись запрещена. Для неё нужно явно передать `{ writable: true }`.
При изменении обновляются только переданные поля; `NULL` и пустая строка различаются.
Внутри транзакции вызовы нужно выполнять последовательно с `await`.

Ключ записи — массив строк; поддерживаются составные ключи. Страница содержит
до 100 записей. Следующая страница запрашивается по `nextKey`; `null` означает конец.
Поля доступны по `columns[].dataKey`: обычно это имя, при повторении имён — ID поля.
Неточные для JavaScript числа возвращаются строками; `sourceJson` сохраняет точное
JSON-представление текущих SQL-значений. Архивный `_copy_source` для рабочих чтений не используется.

## ID, связи и ошибки

Существующие ID сохраняются. Для нового числового ID используется счётчик PostgreSQL,
связанный со столбцом. Если его нет, создание блокируется. Пропуски после отката нормальны.
Составные и нечисловые ключи передаются явно; менять существующий ключ нельзя.

Повторная привязка той же пары не создаёт дубль. Удаление записи с входящими связями
блокируется. Чтения и записи используют соответствие физических имён из
`copy_meta.inventory`, поэтому переименование таблиц для Noco не меняет исходные ID.

Неизвестный результат сохранения возвращается как `commit_uncertain`.
Автоматического повтора нет: сначала нужно прочитать состояние.
Ошибки не выводят SQL, значения строк и секреты.

## Границы

Разрешены только помеченные базы `unicorn_noco_copy` и `unicorn_noco_copy_restore`.
CRM и переходы к её таблицам запрещены. Подключение — через локальный SSH-туннель
или TLS с проверкой сертификата. Соединения закрывает вызывающий код.

Формулы и Lookup вычисляет подключённая Noco. Рабочий SQL-клиент не выдаёт архивные
значения этих полей за актуальные; связи предоставляет через `listRelated`.
Дополнительные поля CV описаны отдельно в `copy_meta.inventory` и не теряются
при обновлении сохранённых строк импортёром.

`identity-plan.mts` только готовит SQL для выдачи ID. Его применение — отдельная
операция с backup и проверкой. `identity-preflight.mts` ничего не создаёт.

## Проверки

Node 24.20.0: `npm run postgres:test`, `npm run db:postgres:test`,
`npm run web:sql:test`, `npm run typecheck`.
Тесты используют подставные подключения. Проверка настоящей базы:
`npm run sql:check -- <путь-к-локальному-ENV>`.
