# Разовая копия Noco в PostgreSQL

Это отдельный инструмент выгрузки и подготовки SQL. Он не переключает приложение,
не меняет исходную Noco и не запускается вместе с backend.
Для подключения другого ПК к уже подготовленной базе он не нужен:
см. [SQL_START.md](../../../../../docs/SQL_START.md).

## Выгрузка и подготовка

Node 24.20.0. Каталог данных должен находиться вне Git и иметь закрытый доступ.

1. `npm run noco:copy -- check <env-file> <preflight-dir>`.
2. `npm run noco:copy -- export <env-file> <round-dir>`.
3. `npm run noco:copy -- prepare unused <round-dir> [previous-rounds...]`.
4. Проверить отчёт расхождений и полученные SQL-файлы. Применение — отдельный шаг,
   только после backup, проверки целевой базы и отсутствия других писателей.
5. После разрешённой загрузки выполнить подготовленный `verify.sql`.
   Затем проверить дамп восстановлением в отдельную базу.

`bootstrap.sql` предназначен только для первоначального создания помеченной
тестовой базы. Не запускать его ради обновления кода на другом компьютере.
Неизвестную базу или роль с тем же именем инструмент не перезаписывает.

После переименования SQL-таблиц или полей передать в `prepare`
`--sql-inventory <absolute-json-file>`: актуальные строки `copy_meta.inventory`
в виде массива `{id, definition}`. Этот файл содержит описание конкретной базы,
хранится отдельно от Git. Без правильного соответствия импорт останавливается.

## Что сохраняется

- Таблицы, исходные ID и доступные значения: числа, даты, Unicode, пустые строки и NULL.
- Полные связи, включая связующие таблицы. Счётчик записей не заменяет сами связи.
- Описание формул и сохранённые значения. Сам импортёр формулы не вычисляет.
- Исходный JSON в `_copy_source` и ключ в `_copy_id`; рабочий код читает SQL-колонки.
- Дополнительные SQL-поля у сохранённых строк и их отдельные описания.
- Существующие значения недоступных полей: они не заменяются выдуманным NULL.

`*.coverage.json` перечисляет недоступные поля. `source-issues.json` —
ссылки на отсутствующие записи. Исходные ошибки не исправляются автоматически.
Если появятся вложения, неподдержанное скачивание блокирует завершение;
одни ссылки не считаются полной копией файлов.

## Безопасность повторной загрузки

Выгрузка проверяет страницы, ID, дубли и конец списка. Четыре завершённых запроса
к Noco — пауза минимум секунду; при 429 учитывается весь Retry-After.
Незаконченная таблица перечитывается; законченная используется только после проверки.

Удаление из SQL допустимо после отсутствия записи в двух завершённых чтениях
и проверки зависимостей. SQL-only изменения сначала сверяются отдельно:
наличие выгрузки не разрешает их перезаписать.
Счётчики ID назад не откатываются.

`verify.sql` сверяет ID, значения и связи. Два совпавших чтения работающей Noco
не гарантируют снимок всех таблиц на одну секунду. Перед рабочим переездом
нужны остановка писателей, обновление данных и отдельная финальная проверка.

Полный повторный импорт поверх последней настройки тестовой Noco ещё не подтверждён.
Не считать unit-тесты разрешением повторить его на рабочей базе.

## Проверки

`npm run noco:copy:test`, `npm run postgres:test`, `npm run typecheck`.
Используются подставные данные. Реальные выгрузки, дампы, ENV и SSH-реквизиты
не входят в Git. Локальные скрипты обслуживания конкретного VDS не нужны для запуска приложения.
