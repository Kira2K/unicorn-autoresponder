# Локальная проверка LinkedIn

Стенд обслуживает собранный интерфейс на loopback. Сначала `npm run web:build`.
Занятый порт — ошибка запуска; чужие процессы не завершаются.

## Быстрая разработка без лимитов

`npm run linkedin:local:mock` → http://127.0.0.1:4321

| Экран | Вход | Пароль |
| --- | --- | --- |
| Ученик: смена прокси | linkedin-local-901@example.invalid | 1234 |
| Ученик: новая заявка | linkedin-local-902@example.invalid | 1234 |
| Денис | local-denis | local-test-only |

Данные в памяти; перезапуск очищает стенд. Прокси `socks5://mock:mock-only@proxy.example.invalid:1080`
проходит проверку страны, `wrong.example.invalid` возвращает неправильную страну.
Все внешние системы, включая уведомления, подменены. Это не доказательство реальной доставки писем.
Для имитации открытия/закрытия после выдачи доступа доступны только в mock:
`POST /__mock__/profiles/{id}/start` и `/stop`. ID виден в карточке/ответе статуса.

## Проверка с настоящим Octo

Используются существующие `.env`, `.env.octo-pilot`, `.env.octo-onboarding`.
Нужны `OCTO_CONTROL_URL/SECRET`, настройки SQL и Octo, доступный приватный проверяющий
сервис `PROXY_CHECKER_BASE_URL/UNICORN_PROXY_CHECKER_SECRET_KEY`, собранный интерфейс.
Ключи/пароли не вставлять в отчёты. Запуск не меняет ENV и не публикует приложение.

```powershell
npm run linkedin:local:migrate
npm run linkedin:local:migrate -- --apply
npm run linkedin:local:checker
npm run linkedin:local:prepare
npm run linkedin:local:live
```

Миграция по умолчанию откатывается, проверяет маркер рабочей БД и повторное применение.
Применение добавляет поле/защиту пересылки и приватную таблицу операций переезда.
Старые подтверждения не создаются. Вход в локальный live-кабинет: http://127.0.0.1:4320.

По умолчанию run ID `20261106-local`. Для другого запуска передавать одинаковый
`--run-id` в prepare, live, E2E и cleanup.

| Экран | Вход | Пароль |
| --- | --- | --- |
| Существующий тестовый LinkedIn / переезд | linkedin-cycle-20261106-local-auto@example.invalid | 1234 |
| Новая заявка | linkedin-cycle-20261106-local-manual@example.invalid | 1234 |
| Денис, только тестовые заявки | local-denis | local-test-only |

В prepare создаются только два помеченных ученика с ролью «фейк», статусом paused,
синтетические реквизиты существующего LinkedIn и намерение подготовки Octo для первого.
Настоящего LinkedIn по этим реквизитам нет: автоматическая регистрация и вход на сайт не выполняются.
Для текущего запуска созданы ученики 306/307 и профили 432 (RU) / 433 (EN).
К EN подключён проверенный исходный тестовый прокси с экспертной отметкой.
В последующих запусках для первого ученика настрой исходный тестовый прокси через обычную форму подключения Octo.
Заполни ответ об английском в анкете, затем используй «Сменить прокси» с другим
работающим тестовым прокси нужной страны. Второй ученик предназначен для Outlook-формы и заявки Денису.
Для него через локальную форму уже создана заявка **№52 «Илья Проверкин»**, EN-профиль **435**.
Сохранены синтетические реквизиты результата, подтверждение пересылки и проверенный
прокси. Пользователь завершил её у Дениса статусом «сделана экспертом».
Этот статус окончательный: ученик сразу получает готовый аккаунт и доступ Octo,
заявка исчезает из очереди Дениса. У администратора остаётся история без подтверждения.
Настоящие Outlook и LinkedIn по этим реквизитам не создавались.

Работает **действующий удалённый Octo-worker**, с общей SQL-базой и конфигурацией папок.
Локальный процесс не запускает второй Octo-worker, lifecycle, Connection Inviter или CRM.
Получение доступа проверяет реальную готовность worker для конкретного профиля.
После открытия дождись штатного окончания доступа и cleanup. Не применяй force-stop.
Новые уведомления переезда обрабатываются только для тестовых учеников. Завершение
цикла локальной фикстуры резервирует доставку в своей транзакции, прежде чем его сможет
забрать старый production-worker; локально доставляются только эти помеченные события.
Общие production-очереди локально не запускаются. 06.11 пользователь разрешил новый
ID той же тестовой группы после миграции: `-1003804004336`, топик **1 (Общий)**.
Локальный отправитель направляет туда только уведомления помеченных тестовых учеников.
Для Общего Telegram требует не указывать `message_thread_id`; другие топики не используются.
Уведомление ученику 52 доставлено: Bot API вернул сообщение 10, журнал содержит `sent`.
Уже отправленный ботоотчёт не повторялся. ENV-файлы и общая Bot API интеграция не менялись.
Для будущего чистого прогона исходный прокси можно задать операторской командой
`npm run linkedin:local:seed-proxy -- --proxy-uuid UUID`. Она принимает только свободный
помеченный тестовый прокси, проверяет подключение и отсутствие использования той же
строки в других активных профилях, затем ставит назначение для проверенной фикстуры в очередь.
Список кандидатов и готовность worker: `npm run linkedin:local:status`.
Уведомления обычного подключения существующего LinkedIn на этом локальном стенде
не ставятся в общую production-очередь; уведомление нового переезда проверяется отдельно.

## Автоматические проверки

```powershell
npm run linkedin:proxy-move:test
npm run linkedin:proxy-move:e2e:mock
npm run linkedin:proxy-move:e2e:live
npm run linkedin:proxy-move:e2e:live -- --apply --run-id 20261106-local
npm run linkedin:local:creator:e2e -- --apply
npm run linkedin:cycle:live -- --with-proxy-move
```

Самостоятельный live-E2E по умолчанию делает предварительную проверку.
Локальный checker запускается отдельно в своём терминале на 127.0.0.1:8002 через
существующее Python-окружение `C:/Users/kiras/proxy_checker_client/.venv`.
Каталог/URL можно указать через `LINKEDIN_LOCAL_CHECKER_DIR/URL`; ENV-файлы не меняются.
Нужен `LINKEDIN_PROXY_MOVE_TEST_PROXY_UUID`: UUID свободного сохранённого прокси,
помеченного test/e2e/demo, с фактическим IP нужной страны. Его выбирает оператор;
сканирование и многократный перебор прокси не выполняются. До `--apply` назначений нет.
`linkedin:local:creator:e2e` проверяет локальную фикстуру 307 и заявку №52:
ввод из браузера, подтверждение прокси, изменение/возврат реквизитов, настоящий
временный доступ, открытие и штатное закрытие Octo, окончание доступа, reload,
сохранение синтетического результата и редактируемого статуса. При повторном запуске
уже подтверждённое назначение и завершённый доступ не повторяются. Отчёт находится
в `tmp/linkedin-local-creator-live/report.json`; реквизиты в отчёт не попадают.
Ответ тестовой анкеты для live-E2E задаётся `LINKEDIN_PROXY_MOVE_TEST_ENGLISH_READY`
(`Yes` по умолчанию, либо `No`); изменение применяется только к проверенной фикстуре.
Повторный запуск продолжает сохранённую операцию, не назначает другой прокси.
Общий E2E включает тот же модуль только с `--with-proxy-move`, после основных циклов,
и использует уже созданного ученика. Для локального общего E2E укажи
`LINKEDIN_E2E_CONSOLE_URL=http://127.0.0.1:4320` и тот же run ID стенда.
Для общего E2E подготовь **новый** run ID через
`npm run linkedin:local:prepare -- --run-id 20261106-full --full-cycle` и запусти
кабинет с `--run-id 20261106-full`: режим не заполняет существующий аккаунт и оставляет
фикстуру чистой для двух циклов. В runner передай тот же `--run-id 20261106-full`.
Текущий стенд 20261106-local предназначен для ручной проверки и самостоятельного переезда.
Общий live-E2E требует установленной схемы с тремя статусами и двумя получателями
уведомления завершения. В рабочей БД эта схема уже установлена; локальный код приведён
к ней. Отдельного шага «выполнение подтверждено» больше нет.
Для уже завершённой заявки 52 используй `npm run linkedin:local:completed:e2e`:
он только читает состояние, проверяет готовый кабинет и предупреждение прогрева,
не выдаёт новый доступ и не повторяет цикл. Отчёт — `tmp/linkedin-local-completed/report.json`.

Успешный mock-E2E проверяет реальные маршруты, сервис и worker с подменными адаптерами:
переезд, восстановление после reload, закрытие доступа, отсутствие дублей, форму пересылки
и сохранение подтверждения у Дениса при открытии/истечении/закрытии доступа.

## Ручной чек-лист и очистка

1. В новой заявке нажми сохранение без галочки пересылки: появится окно, заявка не отправится.
   Открой инструкцию, отметь пересылку и сохрани. Проверь дату у Дениса и повторное редактирование.
2. Сохрани прокси у Дениса, получи доступ и открой профиль. Отметка должна сохраниться
   после закрытия, окончания доступа и reload. Измени реквизит и верни исходное значение.
3. На переезде проверь неправильную страну: прежний прокси должен остаться.
   После успешного назначения открой EN, вручную поменяй страну/город LinkedIn,
   закрой профиль, дождись cleanup и заверши переезд.
4. **Отдельно вручную** проверь включение пересылки в настоящем Outlook, получение
   пересланного письма/кода в Gmail и папку «Спам». Галочка — подтверждение ученика,
   автоматической проверки Gmail или изменения страны LinkedIn нет.

Очистка: `npm run linkedin:local:cleanup` показывает план;
`npm run linkedin:local:cleanup -- --apply` переносит только проверенные закрытые
тестовые профили в корзину Octo, ждёт cleanup действующего worker, архивирует
тестовые аккаунты/учеников и очищает пароли/старые реквизиты в истории переезда.
История теста сохраняется; исходные ученики и подписки поставщика не затрагиваются.
При неизвестном результате удаления сначала выполняется чтение, повторного DELETE нет.
Для нового прогона после архивации используй новый run ID.
Контракт корзины: [Octo Profiles API](https://github.com/octobrowser/documentation/blob/main/api/profiles.md#delete-profiles).

CRM пока не подключена. Событие в `noco.linkedin_proxy_move.data` содержит уникальный ID,
привязку к аккаунту, `completedAt`, `pauseUntil` (+48 часов). Будущий обработчик обязан
дедуплицировать по ID, учитывать точное время и новый цикл аккаунта. Тестовый обработчик
`crmProxyPause` возвращает «Пауза» до границы и «Раскачка» после неё; реальный статус не меняет.
