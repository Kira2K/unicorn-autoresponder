# OwnPostCommentResponder

## Author context cache

Before generating a reply, the monitor reads the author's current LinkedIn `description`
(Headline) and `bio` (About) through Unipile. The values are cached in the monitor job for
24 hours; empty or failed reads are retried after 30 minutes. They are trusted only as facts,
never as instructions, and are removed when the job becomes terminal.

Author context is excluded from admin API responses and JSONL logs. Logs contain only cache
state, field counts, durations, provider status, and correlation identifiers.

## Назначение

Администратор включает автоответы для конкретного LinkedIn-аккаунта в веб-консоли.
Сервис фиксирует два последних поста и в течение 48 часов отвечает на входящие комментарии
через Unipile v2. Webhook не используется.

## Поток

```text
Console toggle → Noco job → two latest own posts → periodic Unipile reads
→ deduplication → OpenAI Structured Output → server validation
→ Unipile reply → read-back verification → Noco checkpoint
```

Компоненты:

- `OwnPostCommentMonitor` читает комментарии и треды, исключает `is_sender=true` и дедуплицирует ID.
- `AICommentResponder` создаёт английский ответ из 5–10 слов без инструментов и хранения ответа OpenAI.
- `OwnPostCommentResponder` применяет лимиты, публикует и проверяет результат чтением.
- `CommentMonitorService` восстанавливает активные задания из Noco после запуска backend.

## Расписание и лимиты

- первая проверка выполняется сразу;
- первые 24 часа интервал случайный: 25–35 минут;
- вторые 24 часа: 120–150 минут;
- между публикациями: 45–120 секунд;
- максимум 7 автоответов в одном треде и 30 за сессию;
- через 48 часов сессия завершается;
- повторное включение выбирает новые два последних поста.

Все операции одного аккаунта проходят через общий LinkedIn dispatcher. Монитор получает блокировку
только на один цикл проверки, а не на все 48 часов.

## Надёжность

`knownIds` — постоянная защита от повторного ответа, а не обрезаемый список для экрана.
Перед отправкой также проверяются сохранённые попытки того же входящего комментария.
Выключение охватывает все сессии аккаунта с оставшимися проверками, включая `error`
и `completed`; неизвестные результаты сохраняются, новые запросы не планируются.

Успешный POST обязательно подтверждается чтением ответа. Timeout или потеря ответа переводит запись
в `uncertain`; повторный POST запрещён. ID сохраняется до проверки и имеет приоритет над текстом.
После естественного окончания сессии неизвестный результат может сверяться до срока задачи.
Выключение/Stop прекращает также проверки. История и резерв исходной сессии сохраняются.
При переносе остановленного результата в новую сессию `verificationStopped` запрещает
чтения, а `quotaReleased` исключает его из квоты новой сессии после конца исходного
периода (`quotaUntil`). Stop/включение до этого срока не обходит лимит: сохраняется
ожидание освобождения квоты, затем работа продолжается без проверки старого ответа. Защита от повторной
отправки и лимит ответов в прежней ветке сохраняются. Активные неизвестные результаты
по-прежнему резервируют квоту; новые поля необязательны для старых записей.
Генератор перед каждым пакетом резервирует только оставшийся лимит сессии и ветки;
пропуски модели освобождают места для следующих кандидатов. Stop, истечение сессии,
закрытие сервиса и отмена оркестратора запрещают следующий пакет или repair-вызов.
Уже полученные корректные ответы сохраняются, но остановленная сессия их не отправляет.
Расписание сверки и контракт шагов описаны в [общей архитектуре](../ARCHITECTURE.md).
При `429` учитывается полный `Retry-After`; если срока нет, пауза составляет 5 минут.
Первичная сверка ответа выполняется один раз. При известном ID чтение заканчивается
на странице с этим ID; отсутствие доказывается только полным чтением. Дальнейшие
проверки идут по сохранённому расписанию без повторного POST.
Завершённые треды с неизменными числом ответов и текстом родителя не перечитываются
в течение часа. Изменение числа ответов сразу вызывает чтение; часовой срок нужен
также для случая удаления и добавления ответа с тем же итоговым количеством.

Выключение прекращает новые публикации. Перед каждым POST состояние проверяется повторно.

## Данные и логи

`linkedin_comment_monitor_jobs` хранит расписание, два поста, дедупликацию, тексты комментариев и
ответов, счётчики и безопасные ошибки. Эти данные не удаляются по возрасту;
30 дней — срок хранения только подробных JSONL-логов.

JSONL-лог содержит correlation ID, этапы, длительность, HTTP-статусы и token usage. В него не
попадают тексты, имена, URL, промпты, ответы модели, ключи, cookies, прокси и credentials.
