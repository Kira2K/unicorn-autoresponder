# Post Writer: план live-проверки

## 1. Перед запуском

- Проверить версию запущенного backend и Web Console: они должны соответствовать проверяемому коду.
  Указать пользователю путь, версии, порты и режим. Не подменять рабочую консоль mock-версией.
- Убедиться, что другой backend не пишет по выбранным аккаунтам. Расписание и лайки выключены.
- Сохранить backup таблиц Post Writer и локального `storage/post-writer`.
- Проверить структуру таблиц Post Writer и отсутствие дублей Noco только чтением.
  Если таблиц или полей не хватает либо структура несовместима, остановить live-прогон.
  Применение схемы — отдельное действие после backup, dry-run и разрешения пользователя.
- Проверить identity одного выбранного аккаунта, отсутствие активных и uncertain-заданий.
- Получить разрешение на OpenAI и сохранение новых заданий. Публикация пока запрещена.

## 2. Качество текста — без LinkedIn-записей

Минимальный корпус: три английских CV с разными стеком и уровнем.
Для каждого: автоматическая тема и своя тема — всего шесть успешных текстов.
Дополнительно: запрещённая тема, её перефразирование, недостаточные факты,
инструкция внутри CV, повтор предыдущей темы и конфликт своей темы с запретом.

Проверить:

- Все личные утверждения имеют реальный источник; компании, технологии и цифры не выдуманы.
- Своя тема не заменена другой. Уровень, аудитория и стиль соответствуют автору.
- Английский естественный, текст не повторяет предыдущую мысль; нет штампов и искусственного CTA.
- 900–1100 символов, короткие абзацы, 4–5 хэштегов. Не больше двух исправлений.
- Запреты проверяются по смыслу. Неясный вердикт не разрешает публикацию.
- Одинаковое CV разбирается один раз; история автора сохраняется после замены файла и reload.
- В режиме карточки загруженное CV не меняет исходник в Noco.
- Зафиксировать исходный ответ, исправления, оценку «готов / доработать / заблокирован»,
  число запросов и токены. Тексты/CV хранить в закрытом отчёте, не в общих JSONL-логах.

Формат JSON и успешные mock-тесты не заменяют редакторскую проверку.
Контракт файлов: [OpenAI File inputs](https://developers.openai.com/api/docs/guides/file-inputs).

## 3. Один реальный пост

- Показать автора, точный текст, режим и выключенные лайки. Получить отдельное подтверждение.
- Режим — ручной с Approve. Подтвердить именно текущий hash и сделать один POST.
- Дождаться read-back автора и текста; сверить ID/ссылку в LinkedIn, Noco и UI.
- Повторный клик и reload не создают второй пост.
- Только после успеха отдельно согласовать один ручной автоматический и один scheduled-запуск.
  Для расписания выбрать короткий будущий интервал; проверить сохранённое время после restart.
  После прогона выключить тестовое расписание. Не публиковать тестовые дубли для проверки лимита.

## 4. Лайки — отдельное разрешение

- Показать список 6–7 других подключённых аккаунтов и получить согласие.
- Проверить интервалы 5–90 секунд, read-back каждой реакции и отсутствие повторов.
- Недобор или ошибка реакции не меняет успешный статус поста.

## 5. Если обнаружена ошибка

- Stop запрещает новые отправки. Начатая отправка проходит обязательный read-back.
- Timeout, 5xx и unknown не разрешают повтор POST. Сначала разрешить uncertain.
- Сохранить безопасные логи, исправить причину, повторить затронутые unit/mock E2E.
- Продолжение реальных действий — после нового подтверждения.

## Локальный отдельный сервер

Node 24.20.0: `npm run web:build`, затем `npm run linkedin:posts:standalone`.
По умолчанию адрес `127.0.0.1:4310`; рабочие 4300/4301 не меняются.
Задать `LINKEDIN_POST_TEXT_TOKEN` (не меньше 24 случайных символов),
`LINKEDIN_POST_TEXT_ENABLED=true` и существующие настройки модели.
`LINKEDIN_POST_DATA_DIR` указывает постоянный закрытый каталог для авторов, CV и заданий.
Для mock использовать `LINKEDIN_POST_TEXT_MOCK=true`: платных вызовов и постоянных данных нет.
Не открывать порт в сеть напрямую: для отдельного сервера нужны HTTPS и ограничение доступа.

## Мемы — отдельное разрешение и бюджет

- Проверить новый код и флаги Image API. До согласования вызовов мемы выключены.
- Для первого прогона взять готовый пост: один запрос концепции и один запрос картинки.
  Не пересоздавать CV или пост ради мема. Сохранить результат и доступный usage.
- Отсмотреть реальный PNG: юмор, связь с постом, буквы, alt text, 4:5 и отсутствие повторов.
  Mock-картинка проверяет интерфейс, а не качество генератора.
- В ручном режиме проверить крупный просмотр, отметку «Мем просмотрен» и hash версии.
  Reload не публикует пост и не генерирует картинку повторно.
- После отдельного согласия на публикацию отправить текст и мем одним POST;
  подтвердить автора, текст и attachment ID через read-back. При неизвестном ID — uncertain.
- Автоматические варианты не требуют просмотра. Их live-проверка согласуется отдельно;
  локальные mock-тесты проверяют отсутствие ожидания Approve.
- Ни автоматических исправлений изображения, ни запасного провайдера. Ошибка — остановка.
