# LinkLab

Таблица Noco хранит данные в PostgreSQL. Существующий worker CRM получает
изменения, применяет правила задач и возвращает подтверждение. Отдельного
сервиса нет. Кабинет и бот используют SQL; HTTP-вызовов CRM при сохранении нет.

## Что делает код

- После сохранения LinkedIn с логином и паролем создаёт одну передачу ученика
  в LinkLab. Повтор не сбрасывает статус и не отправляет новую передачу.
- При нескольких аккаунтах выбирает только единственный с корректным LinkedIn URL.
  Неоднозначность не разрешает выбором первой записи. Пароли в LinkLab не копируются.
- На штатном подтверждении финального EN CV учеником сохраняет дату вместе
  со статусом и историей CV. RU-переходы и условия Profile Filler не меняются.
- Хранит отдельную роль Clients: клиент, ученик, реферал, фейк либо пусто.
  Роль не влияет на статус, задачи или права.
- Хранит версии изменений и подтверждения CRM. До подтверждения вид показывает
  ожидание либо ошибку, а не успешную синхронизацию.

Статусы: Новый, Прогрев, Раскачка, Пауза, Блок, Завершен. «Новый» ждёт ручного
перевода в работу. «Завершен» отменяет только незапущенные автоматические задачи.

## Прокси, даты и профиль

Прокси-пауза длится 48 часов: статус становится «Пауза». CRM отменяет текущие
и попадающие в паузу задачи, включая начатые, с причиной «Изменение прокси».
Прогресс и история остаются. Задачи на день окончания доступны только после
точного времени окончания. Отменённые задачи сами не восстанавливаются.
В общем пакете отменяется участие затронутого ученика; нужна ручная замена.
Исходный статус возвращается, если сотрудник за время паузы не выбрал другой.
Сам прокси код не заменяет.

CRM считает процент по существующим 21 отметке и сохраняет первую дату 100%.
Дата блока меняется только при новом переходе в «Блок». Новый аккаунт можно
создать через 30 календарных дней по Москве. Новый URL не заменяет действующий.
События хранятся в UTC, экран показывает московское время. Исторические даты
не подставляются из updated_at или времени импорта.

## Установка и выключение

`LINKLAB_ENABLED=0` — режим по умолчанию. При старте схема не создаётся.
Перед включением нужны SQL-миграции `sql/001`–`005` по порядку и совместимая CRM
с её миграциями. Запускать вручную владельцем схемы, с остановкой на первой ошибке.
Старых учеников сначала сопоставить с сохранением их статусов и без уведомлений.
Схема сама этого не делает. `unicorn_noco_copy` — рабочая база, не тестовая.

SQL-права выдаются отдельно:

- Noco читает LinkLab, меняет только status, new_account_url, proxy_state.
  Роль редактируется в связанной Clients. Схему, служебные поля и результаты CRM
  менять нельзя. Скрытие колонки не заменяет запрет SQL.
- Unicorn читает источники выбора аккаунта, создаёт LinkLab, использует её
  sequence, отмечает handoff/source события и пишет linklab_cv_approvals.
- CRM читает очередь и результаты, вызывает функции подтверждения/изменения.
  После миграции 005 нужен EXECUTE на noco.linklab_refresh_credentials().
  Функция обновляет предупреждение о неполном аккаунте, не возвращая паролей.
  Доступ PUBLIC к новым функциям закрыт; широкие права не требуются.

Выключение LinkLab не удаляет данные. Кабинет и CV возвращаются к прежнему
сохранению. CRM прекращает обмен и явно отклоняет новые изменения статуса
связанного ученика; обычные карточки и несвязанные ученики работают.
Активные паузы остаются защищены; для автоматического завершения нужен worker.
Перед плановым отключением завершить циклы и доставить очередь.
Таблицы CRM после установки нужны коду даже при выключенном обмене.

Откатывать SQL после появления новых данных нельзя вслепую: down-миграции
проверяют условия. Сначала сохранить и сверить данные. Откат 005 возвращает
старую связь сохранения аккаунта с LinkLab; сначала остановить новый worker.

## Экран Noco

Настройки полей и порядок заданы в `noco-display.mts`. Роль, стек, имя и текущий
URL читаются из связанных записей, без второй редактируемой копии.
Даты и проценты отображаются формулами поверх значений SQL.
Перед настройкой проверить `validateNocoCatalog`; дубли не удалять автоматически.
`planNocoDisplay` требует полного описания колонки. Общий Meta Sync старого
источника не запускать: он может затронуть другие таблицы.
После каждой настройки проверить SQL и повторное чтение экрана.

## Проверки

Node 24.20.0 использовался для проверок; новых npm-зависимостей нет.
Unit: `node --test src/features/linkedin-automation/linklab/*.test.mts`.
SQL-наборы без отдельной конфигурации пропускаются, что не считается успехом SQL.
Для них `LINKLAB_ISOLATED_PG_CONFIG` указывает JSON одноразового локального
PostgreSQL: host, port, user, password, database, target_database, local_proof=true.
Host — loopback; имена баз — linklab_*_test_*. Нужны две пустые отдельные базы.
Тесты создают искусственные источники; рабочие ENV не подключать.
`base-query.sql.test.mts` отдельно использует `LINKLAB_SQL_TEST_ENV` и базу
unicorn_noco_copy_restore, с временными таблицами и откатом транзакции.

Перед выпуском проверить именно собранные версии Unicorn и CRM, права их ролей,
ошибки сохранения в облачной Noco и одного искусственного ученика со всеми этапами.
Локальные тесты не подтверждают работу облачной Noco или доставку Telegram.
При неизвестном результате уведомления CRM не повторяет отправку вслепую.
