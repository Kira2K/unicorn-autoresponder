# Working in external-responses

- Start with the affected stage's `README.md`. Use the feature README as a routing index; do not load every stage or historical application artifact for a local change.
- For application operation, start with `application-status --input FILE --worker-packet [--position ID]` and the current authorized budget/session handle. Read referenced details only when the reported next action needs them. Do not reread unchanged code, CVs, full reports or this conversation to reconstruct saved state.
- When delegation is already authorized, use one fresh Sol worker (`fork_turns="none"`) for a bounded application task. Do not reuse a long-lived development worker for browser operation or copy the conversation into its task. Preserve the browser process independently; a fresh worker must never take over a busy profile. Reuse the worker only within its current narrow task.
- The coordinator routes scope and receives the result; it does not repeat the worker's browser inspection or run a second review loop by default. Tests/checks run in code with compact results; repeat only after relevant changes or failures. No new worker, model fallback, paid call or weekly allowance is authorized by these instructions.
- Global vacancy rules are authored only in `.agents/skills/vacancy-selection/SKILL.md`, read automatically by classification. Do not introduce a SQL global-rule editor or duplicate those rules in code; DB stack descriptions and personal student restrictions have separate purposes.
- Read its public entry point, referenced contracts and relevant tests next. Read neighboring implementations only when their contract is affected.
- Keep stage inputs, outputs, side effects, errors, extension points and test pointers documented alongside that stage. Update the local README when changing its contract.
- Preserve the pipeline boundary: all company targets accounted for by real/valid weekly reused scans, global stack/market selection, matching authorized student cohorts, personal restrictions/history, then CV preparation and applications. The feature README and affected stage contracts describe current behavior; older planning documents retain historical proposals.
- `company_sources/sources.md` owns the heterogeneous source registry. Prepare sources through format-specific readers before company collection; file-read coverage is not website/vacancy coverage. Preserve missing/deferred/blocked entries and exact provenance.
- Student eligibility is stack/market match plus no applicable restriction. Policies are stored data evaluated in context; do not add hardcoded employer/city lists or hidden CV-fit gates. Confirmed closed vacancies leave active pools without deleting history/evidence.
- `noco.vacancies` contains accepted vacancies only: promote a discovery after shared selection passes and at least one selected populated stack matches. Raw, excluded, review-only and missing-description observations belong in collection audit/checkpoints, never in the vacancy directory. Collection persistence must not bypass classification.
- Market follows the description language: English -> Global, Russian -> Ru, other/ambiguous -> unknown. Company jurisdiction must not override this operator rule. Standard scans store confirmed listing access gates in SQL source state and run audit; independent legacy collection retains its local queue. Do not retry pending gates without resolution/explicit retry or create accounts. Application-only registration is not a listing access wall.
- Keep runtime reads separate from explicit migrations. Test external writes with mock adapters or intercepted browser fixtures.
