# Консоль с PostgreSQL

`APP_DB=postgres` подключает SQL к обычной консоли: кабинет, аккаунты,
CV, состояние Telegram и хранилища LinkedIn. Маршруты API, роли и правила
переходов сохранены. Ошибка SQL не включает запасное чтение из Noco.

[Как запустить на другой машине](../../../../../docs/SQL_START.md).

## Основные файлы

- `repository.mts` — прежние правила консоли поверх SQL-чтений и записей.
- `records.mts`, `selected-clients.mts` — списки и выбранная карточка.
  Не загружают связи всех учеников ради одного входа или CV.
- `writes.mts` — запись переданных полей и проверка владельца.
- `linkedin-repository.mts` — аккаунты LinkedIn и история подключения.
- `app-options.mts` — передаёт SQL-хранилища прежним сервисам.
- `runtime.mts` — проверяет базу и выдачу ID перед обычным запуском.
- `check.mts` — только проверяет SQL, без приложения и внешних действий.

Архивный JSON не используется как текущее состояние. Связи читаются заново;
связанные записи сохраняются в одной транзакции. Неизвестный результат
сохранения не повторяется автоматически.

## Поля CV

`last_responsible`, `last_workflow_error`, `workflow_trace` хранятся в SQL
как дополнительные nullable TEXT-поля. Их описание отделено от исходной схемы Noco.
Правила статусов и уведомлений не меняются.

`workflow-fields.mts` перечисляет необходимые поля CV, а `check.mts` проверяет
их наличие. Создание полей и другие изменения структуры выполняются отдельно
через SQL. При запуске приложение не меняет схему.

## Проверки без отправок

`npm run web:sql:test` использует подставную БД и внешние сервисы.
`npm run sql:check -- <ENV>` читает настоящую SQL, но не запускает приложение.

`createSqlTestConsole` — отдельная сборка для приёмки. Записи требуют списка
разрешённых искусственных учеников; CV и LinkedIn включаются отдельно.
Внешние отправители заменены заглушками, скопированные задания не возобновляются.
Нельзя выдавать её успешный тест за проверку настоящих Telegram/HH/LinkedIn.

Обычные `web:backend` и `web:start` используют настоящих провайдеров и могут
восстанавливать задания. Сам выбор SQL их не отключает.

## Сохранённые старые ограничения

Два одновременных создания CV могут дать две записи, как и в старом хранилище.
Исполнитель подключения LinkedIn может подавить ошибку записи истории.
Эти правила не исправлялись попутно; сравнения со старым кодом есть в тестах.
