# Запрос backend-агенту proxy-checker: точные коды NodeMaven

Console получает географию из каталога NodeMaven и передаёт выбранные `code` без преобразования. Каталог реально содержит город `donostia_/_san_sebastian` (Spain → Basque Country). Старый валидатор `[a-z0-9_]+` отклоняет этот код.

## Изменение контракта

- В `POST /v1/proxies/best` сохранить ISO-код страны; `location.region` и `location.city` принимать как точные коды каталога длиной 1–200 символов, включая `/`, апострофы и Unicode. Не заменять символы и не переводить код в нижний регистр.
- Отклонять управляющие символы и значения вне выбранной иерархии каталога. Регион и город обязательны, если соответствующий уровень имеет варианты.
- Передавать выбранный код провайдеру без потери значения. Если шлюз провайдера не поддерживает конкретный код, вернуть явную ошибку, не выбирать другую географию.
- Проверять фактический город по подтверждённым вариантам названия из каталога (например, Donostia / San Sebastian), без произвольного нечёткого сравнения.
- Сохранить `BestProxyResponse` с одним `best_proxy`, существующие лимиты и `count=20` Console. Обновить `frontend-contract/openapi.json`, `api-types.ts`, `api-client.ts` и README.

Тело запроса для регрессии:

```json
{
  "unicorn_proxy_checker_secret_key": "<service key>",
  "api_key": "<NodeMaven key>",
  "count": 20,
  "location": {
    "country": "es",
    "region": "basque_country",
    "city": "donostia_/_san_sebastian"
  }
}
```

Ожидание: валидный каталоговый код не получает 422 из-за `/`; неизвестный город получает явную ошибку; результат не подменяет заданную географию. Логи не содержат ключа и реквизитов прокси. Console забирает обновлённые файлы после готовности сервиса и повторяет контрактные и реальные проверки.
