# Denis.md: проверка и готовность выпуска, 29 октября 2026

Локальная реализация находится в `test/linkedin-full-cycle-e2e`. Production ещё
не обновлён, миграция 003 в рабочей БД не применялась. Приведённые ниже локальные
результаты не доказывают работу новой версии на Render.

## Реализовано

- В главном админском разделе LinkedIn есть «Подтвердить выполнение» для заявок
  «сделана экспертом». Сервер проверяет результат, владельца, актуальный EN-прокси
  и штатно закрытый профиль. Повторное подтверждение не создаёт второй цикл.
  Сохранение статуса и результат доставки уведомления показаны отдельно.
- Эксперт сохраняет доступ и возможность менять прокси до «выполнение подтверждено».
  После подтверждения задача недоступна эксперту. Ученик перестаёт редактировать
  результат уже на «сделана экспертом».
- Outlook всегда раскрыт, история блокировок включается галочкой с пятью
  обязательными полями. Архивная история читается тем же модулем, что у Дениса.
  Старые неполные данные не переписываются; новые неполные карточки запрещены.
- Будущая дата запрещена и на клиенте, и на сервере. Ошибка: «Дата не может быть
  в будущем». Дата/время Outlook видны Денису и главному админу. Пропуски исходных
  данных Octo возвращают известные названия полей. Поля даты и имени выровнены.
- Локация подставляется из записи ученика; правка анкеты не меняет `real_location`
  ученика. В обращениях к ученику используется «ты».
- Экспертный прокси имеет `isMadeByExpert`. Ученик получает компактный статус,
  без host/port/login/password, даже с запросом реквизитов. Перезапись учеником
  запрещена. Обе админские панели могут прочитать полные реквизиты.
- В течение 30 дней после подтверждения каждое получение доступа сопровождается
  предупреждением о прогреве. Доступ остаётся доступен после подтверждения модалки.
- «Меня забанили» отмечает текущий LinkedIn заблокированным, но не создаёт заявку.
  Модалка предлагает инструкцию восстановления и отдельное заверение «Прошла
  неделя — подать заявку». Серверный недельный таймер не вводится. Связанная почта
  показывается как почта заблокированного LinkedIn. Предупреждение не открывать
  Octo во время регистрации возвращено и для повторной заявки.
- Существующий LinkedIn использует собственный проверенный прокси, по умолчанию
  SOCKS5, без обязательной Outlook-почты и без создания заявки эксперту.
  Сохранение ставит одно уведомление по аккаунту в durable outbox.
- Получатель статуса/подтверждения/существующего LinkedIn передаётся аргументом.
  По умолчанию `@juliafeels`, текущая сборка передаёт `@KiraSamsonova`.
- Live runner подтверждает кнопкой админа и требует `sent` с положительным ID
  Telegram-сообщения. SQL-подтверждение удалено. Preflight проверяет опубликованную
  настройку получателя до любых тестовых записей.

Переносимый скилл: `outputs/skills/linkedin-admin-confirm.zip`, исходник
`outputs/skills/linkedin-admin-confirm/SKILL.md`. Он предполагает готовый доступ
администратора к Octo и использует только админский UI для подтверждения.

## Проверено локально

- Контракты, сервисы, HTTP-права, адаптеры прокси и уведомления: целевые наборы
  прошли. Два SQL-теста, пропущенные в обычном наборе, выполнены отдельно ниже.
- Изолированный PostgreSQL 17 на loopback: 9 проверок без пропусков. Проверены
  rollback/rerun миграции, точный backfill экспертных прокси, конкурирующее
  подтверждение, бан с проверкой владельца без заявки и повторная доставка.
  Одноразовая схема удалена, сервер остановлен. Рабочая БД этим набором не затронута.
- Браузерные проверки: главная админская кнопка, pending/sent, потерянный ответ
  без повторного POST, роли эксперта, прогрев, очистка ранее загруженных реквизитов,
  форма и мобильная ширина. Полный mock-сценарий кабинета прошёл отдельно.
- TypeScript и production build прошли. Предупреждение Vite о размере bundle
  осталось. Новых npm-зависимостей нет.
- Просмотрены новые desktop/mobile скриншоты. Артефакты находятся в игнорируемых
  `tmp/denis-local-qa/` и `tmp/linkedin-octo/`; пароли на снимках замаскированы.

## Ответы на вопросы старого отчёта

28 октября оба пользовательских цикла завершились: анкета, работа эксперта,
настоящий гостевой запуск/закрытие Octo, подтверждение, история и два уведомления.
Тогда подтверждали SQL — это не проверка админской кнопки. Общая приёмка осталась
неуспешной из-за двух ранее существовавших чужих связей LinkLab; число нарушений
до и после одинаково. Верхний «полный прогон» агрегировал это нарушение.
Генератор теперь отдельно показывает общий результат, завершённые циклы и
непройденные проверки. Старый PDF не является доказательством новых функций.

Во время временного доступа штатная защита Octo заменяет видимое имя профиля на
`John Doe <случайный суффикс>` и переносит профиль в гостевую папку. После закрытия
cleanup возвращает сохранённое исходное кириллическое имя и домашнюю папку.
Поэтому «восстановлено кириллицей» описывало завершение временного доступа,
а не исправление неправильного русского имени. Этот механизм не менялся.
У Ильи Проверкина живые названия профилей не проверялись: профили для этого
специально не создавались.

## Что нужно для live-приёмки

1. Отдельно разрешить публикацию этой версии и явную миграцию
   `src/features/linkedin-automation/creation-tasks/migrate-denis.mts --apply`.
   Без `--apply` выполняется только транзакционная репетиция с rollback. Backfill
   помечает только совпавшие student/profile/current UUID с экспертной квитанцией.
   ENV не меняется. Существующий запрет чужих связей LinkLab не обходится.
2. Открыть Octo под настроенным гостем; при проверке был другой пользователь.
   Запустить существующий локальный checker на 127.0.0.1:8002. Preflight должен
   подтвердить новую схему, получателя Киру, гостевые права, bridge и два различных
   рабочих тестовых подключения. Дублирующий production worker не запускать.
3. Выполнить два live-цикла через UI только для новых помеченных `paused`/`фейк`
   фикстур. Проверить свежие экраны, две админские кнопки и два `sent` message ID.
   Реальные аккаунты Outlook/LinkedIn на внешних сайтах не регистрируются.
4. Общий результат нельзя назвать успешным, пока исходные нарушения целостности
   сохраняются. Их исправление требует отдельного решения о правильных владельцах.
   Доставка старого PDF по умолчанию включает Юлию; сегодня её не запускать.

Вместо публикации runner может открыть локальный кабинет через
`LINKEDIN_E2E_CONSOLE_URL=http://127.0.0.1:<port>`. Разрешены только loopback и
штатный production URL. Поскольку production и локальный backend используют одну
БД и один outbox, локальный apply дополнительно требует остановленного production
worker и явного `LINKEDIN_E2E_PRODUCTION_WORKER_STOPPED=1`. Это подтверждение
оператора, а не автоматическая остановка. Без него preflight блокирует любые записи.

До этого шага нет нового полного live-E2E и нет публикации изменений в GitHub.
