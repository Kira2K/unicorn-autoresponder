## Как воспроизвести

Нужен Node 24.20+, установленный проект, Playwright Chromium, рабочие Render/DB
read/write-настройки, локальный Octo под сохранённым гостем и штатный proxy checker.
Секреты берутся из существующего `.env` и Render; не копировать их в аргументы,
коммиты или отчёт. Checker URL по умолчанию `http://127.0.0.1:8002`, переопределяется
`LINKEDIN_E2E_CHECKER_URL`. Runner сам checker/worker/миграции не запускает.

```powershell
npm run linkedin:cycle:test
npm run linkedin:cycle:preflight
# Только после проверки условий и разрешения на реальные тестовые записи:
npm run linkedin:cycle:live -- --run-id <unique-run-id>
```

Без `--apply` основной `linkedin-full-cycle.e2e.mts` выполняет только preflight.
Он не меняет БД/Octo, но делает сетевые проверки подключений и пишет локальный
журнал. Без `--run-id` используется `tmp/linkedin-full-cycle/current.json`;
явный новый ID означает новый набор фикстур. Не менять current.json для обхода
неизвестного результата. Fixture email не является настоящей почтой.

Runner перечитывает собственные записи и не повторяет создание после потерянного
ответа. Неизвестное открытие/назначение требует ручной проверки; оно не получает
статус «пройдено» автоматически. Не запускать два экземпляра одного прогона
одновременно: эксклюзивный `run.lock` блокирует второй процесс. После crash lock
не истекает автоматически; сначала проверить живой процесс, БД и Octo, затем
вручную снять именно этот локальный lock. Новые профили/прокси создаёт штатный
backend, а не отдельный worker.

Для настоящего SQL-набора `LINKEDIN_CYCLE_ISOLATED_CONFIG` указывает JSON только
одноразового loopback PostgreSQL: user `cycle_owner`, port `55439`, database
`unicorn_noco_copy_restore`, `local_proof: true`. SQL-тест проверяет отсутствие
схемы `noco`, создаёт свои синтетические таблицы и удаляет только их. Рабочую БД
для этого теста указывать нельзя. Не запускать два SQL-набора в одной базе одновременно.

Полные mock E2E:

```powershell
npm run web:build
npm run linkedin:intake:e2e
npm run octo:console:e2e:mock
npm run typecheck
```

## PDF и доставка

Python-зависимости перечислены в `linkedin-full-cycle/requirements-report.txt`.
`report.py --report <private-report.json> --output <private.pdf>` создаёт русский
пошаговый PDF. Только после полного успеха можно передать `--private` с локальным
`manual-private.json`. В Git эти файлы не попадают (`tmp/`, `output/pdf/` игнорируются).
Перед доставкой все страницы нужно отрендерить и визуально проверить.

Явная команда доставки:

```powershell
node --env-file=.env src/features/web-console/e2e/linkedin-full-cycle/delivery-cli.mts <run-id> <private.pdf>
```

Она отклоняется без `passed`, двух завершённых циклов и созданного ручного
пользователя. Отправляется один PDF с подписью и данными входа в настроенную
личку Киры и личку Юлии. Результат/хеш документа записываются локально, содержимое
PDF и пароль не логируются. Потерянный ответ, crash после claim и отказ Telegram
автоматически не повторяются; receipt требует ручного разбора. Обычная команда
по-прежнему требует полного успеха. Разовая доставка с известным предупреждением
выполнена отдельно по прямому указанию пользователя через тот же `sendOne` и
durable receipts, без изменения общего результата проверки на «пройдено».

Приватный PDF этого прогона: 17 страниц, каждая отрендерена и визуально проверена;
кириллица извлекается корректно, текст не выходит за страницу. Временные checker
и изолированный PostgreSQL остановлены. Оба live-доступа тестового EN-профиля
завершены; ученики и ресурсы остальных клиентов не очищались и не изменялись тестом.
