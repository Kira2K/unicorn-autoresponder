# Автоматизация LinkedIn: основа

Первый этап добавляет контракты запуска и остановки существующих LinkedIn-фич,
SQL-хранилище настроек, заданий, событий и истории отзывов, а также блокировку
единственного LinkedIn-исполнителя. Планировщик и подключение к backend идут
следующим этапом; этот этап сам не включает автоматизацию.

SQL-код: `src/integrations/postgres/linkedin-automation`. Общие контракты:
`src/features/linkedin-automation/orchestrator/contracts.ts`. Блокировка относится
только к LinkedIn; обычные операции других модулей её не используют.

Изменения фич сохраняют дневную квоту приглашений и ключ автоматического поста,
добавляют безопасную остановку перед отправкой и проверку неопределённого результата.
Постоянный монитор комментариев сохраняет историю и лимиты 48-часовой сессии.
Ручной отзыв приглашений по-прежнему требует подтверждения.

Миграция не выполняется при запуске приложения. SQL-схема создаёт только
`linkedin_automation`; перенос журнала не удаляет исходные файлы. Команда миграции
и инструкция включения появятся вместе с подключением оркестратора.

Проверки: `npm run linkedin:automation:test`, `npm run typecheck` и существующие
регрессии LinkedIn-фич. Для SQL-теста задайте `LINKEDIN_TEST_PG_BIN` — каталог
локальных утилит PostgreSQL 16. Тест создаёт собственный временный кластер на
свободном loopback-порту и не читает реквизиты существующих баз.
