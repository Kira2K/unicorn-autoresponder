# Запуск версии с PostgreSQL

Эта версия заменяет Noco как хранилище приложения. Подключённая к SQL тестовая
Noco остаётся редактором той же базы. Обмена с прежней рабочей Noco здесь нет.
Штатные чтения Google Sheets и локальные файлы остаются на своих местах.

## На другой Windows-машине

1. Получить согласованную ветку или локальный пакет в **отдельную папку**.
   Старую копию, её ENV и данные не перезаписывать.
2. Выбрать Node `24.20.0`. Проверить `node --version`, выполнить `npm ci`.
3. Подготовить локальный ENV на основе существующего. Секреты не отправлять в Git.
   Добавить `APP_DB=postgres` и параметры `APP_DB_POSTGRES_*` из `.env.example`.
4. Настроить доступ к уже существующей `unicorn_noco_copy`: через свой SSH-туннель
   либо TLS с проверкой сертификата. Пароль роли приложения передаётся отдельно.
   Не использовать администратора PostgreSQL или реквизиты CRM.
5. Выполнить `npm run sql:check -- C:\private\unicorn-sql.env`.
   Без аргумента команда читает `.env` в текущей папке.
6. Выполнить `npm run typecheck`, `npm run web:sql:test`, `npm run web:build`.

`sql:check` только читает SQL: проверяет базу, таблицы, дополнительные поля CV
и доступ к выдаче ID. Не меняет схему или строки, не запускает backend, бот,
расписания и внешние запросы. Успех проверки не означает разрешение на отправки
или подтверждение прав на каждую возможную запись.

## Перед обычным запуском

- Проверить сохранённые задания и расписания: среди них могут быть скопированные
  рабочие действия. Не сбрасывать статусы и не удалять историю для обхода проверки.
- Убедиться, что другой ПК, планировщик или сервер не работает с теми же аккаунтами.
  Локальный порт и блокировка не защищают от второго компьютера.
- Завершить старый экземпляр штатно и дождаться начатых операций. Если результат
  отправки неизвестен, сначала проверить его; повторно не отправлять.
- Проверить пути CV, мемов, HH-заданий и Telegram-сессий. Эти файлы не хранятся
  в SQL и не входят в пакет. Сессии не копировать в Git.
- Для рабочего переезда отдельно обновить данные и согласовать переключение.
  Тестовая копия не обязана совпадать с текущей рабочей Noco.

После разрешения: сохранить настройки в локальном `.env`, запустить
`npm run web:backend` и в другом терминале `npm run web:frontend`.
Обычные адреса: backend `http://127.0.0.1:4300`, интерфейс `http://127.0.0.1:4301`.
Не использовать `web:dev` для осторожного переключения: он может завершать
процессы на занятых портах. Занятый порт сначала проверить по PID, не менять молча.

Обычный backend использует настоящих провайдеров и может восстанавливать задания.
`APP_DB=postgres` — выбор базы, **не безопасный режим**.
Бот и HH запускаются отдельно, только после проверки их настроек и разрешения.
`LINKEDIN_POST_WRITER_ENABLED=false` не выключает остальные фичи.

## Если проверка не прошла

Не запускать backend и не применять миграции автоматически. Сообщить код ошибки,
версию Node и выбранную базу; ENV, пароль и строки учеников не прикладывать.
Если SQL недоступна, код не переключается сам на Noco.

До первых записей можно вернуться к сохранённой старой копии и прежнему ENV.
После записей в SQL простой возврат к старой Noco потеряет эти изменения:
сначала сверка и отдельное решение о возврате.

## Что не входит в этот PR

Переключение рабочих процессов, обновление данных из оригинала, настройка VDS,
VPN и CRM, автоматический перенос оформления Noco и постоянная синхронизация.
Данные и серверное подключение Noco не переносятся через Git.
Инструменты разового копирования данных и изменения схемы в PR не входят.
Структуру таблиц меняем отдельно через SQL; в Noco редактируем данные.
