## Включение после слияния PR

Рабочий веб-сервис Render: `Very Evil Unicorn`, ветка `master`. Автодеплой включён, поэтому слияние PR запускает публикацию. В этом изменении PR не сливается и деплой не запускается.

Для пилотного релиза установить в обычных Environment Variables **веб-сервиса**:

```dotenv
STUDENT_PROFILE_TEST_CLIENT_ID=1
VITE_STUDENT_PROFILE_TEST_CLIENT_ID=1
```

Первый флаг включает адаптер в бэкенде и проверяет соответствие ID email пилотного ученика. Второй встраивается при сборке Vite. Фронтенд показывает новый кабинет только при совпадении ID и подтверждающем флаге из ответа бэкенда. Изменение только переменной Vite без адаптера не включает новую форму.

Сохранить переменные без запуска деплоя, если интерфейс Render предоставляет этот вариант, затем слить PR; иначе настроить их при запланированной публикации уже слитого коммита. На старой версии кода переменные не включают кабинет. После настройки обоих флагов требуется сборка и деплой, а не только рестарт процесса.

Сохранить существующие команды сервиса:

```text
Build:      npm install && npm run web:deploy-build
Pre-deploy: node /etc/secrets/unicorn-sql-start.cjs --check
Start:      node /etc/secrets/unicorn-sql-start.cjs
```

Секретный стартовый скрипт сам читает `unicorn-sql.env` и поднимает SSH-туннель. Его окружение и туннель не сохраняются для следующей команды оболочки после `--check`. Не заменять эту проверку миграцией и не менять SQL-секреты, SSH-ключи, persistent disk или настройки `unicorn-bot`.

После публикации открыть кабинет пилотного ученика, проверить загрузку данных, сохранение и повторное открытие компаний; для другого ученика проверить прежнюю форму. Для отключения пилота убрать серверный флаг и опубликовать конфигурацию: ответ API перестанет включать новый интерфейс. Новые колонки и данные при откате интерфейса сохраняются; автоматического DROP или восстановления всего бэкапа поверх текущих данных нет.

## Контракты и ограничения

- Дополнительные поля API: `middleName`, `noHigherEducation`, `currentCompany`, `previousCompanies`; `studentProfileEnabled` возвращается только пилоту при включённом адаптере.
- Компании с галочкой попадают в `current_company`, остальные — в `previous_companies`; значения разделяются запятыми. Пустые списки очищаются до NULL. `stop_list_company` содержит общий список. Отсутствующий ключ в частичном обновлении не очищает колонку.
- Сохранение прежних полей и дополнительных полей остаётся последовательным. Ошибка второй записи может означать, что первая уже сохранена; интерфейс показывает ошибку и сохраняет ввод. Общая транзакция сохранения профиля и новая серверная бизнес-валидация не добавлены.
- Изменения подписей, Username, оформления, строгого ввода и модального окна ограничены пилотным кабинетом. Сохраняется загрузка паролей отдельным защищённым запросом из текущего master; до успешной загрузки сохранение заблокировано.
- Подсказка желаемой локации упоминает `; ` по согласованному тексту. Существующая проверка пока принимает один `City, Country` либо `Remote`; поддержку нескольких локаций это изменение не добавляет.
