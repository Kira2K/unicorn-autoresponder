# Кабинет для всех учеников: БД и Render

После публикации этой версии новый кабинет включается для всех учеников при работе с PostgreSQL, без ограничений по ID или email и без дополнительных переменных Render. При запуске бэкенд проверяет наличие четырёх колонок и подключает адаптер для всех учеников. Проверка не выбирает конкретного пользователя и работает даже в пустой БД. Сохранить существующие команды сервиса:

```text
Build:      npm install && npm run web:deploy-build
Pre-deploy: node /etc/secrets/unicorn-sql-start.cjs --check
Start:      node /etc/secrets/unicorn-sql-start.cjs
```

Секретный стартовый скрипт сам читает `unicorn-sql.env` и поднимает SSH-туннель. Его окружение и туннель не сохраняются для следующей команды оболочки после `--check`. Не заменять эту проверку миграцией и не менять SQL-секреты, SSH-ключи, persistent disk или настройки `unicorn-bot`.

Отдельно проверить прежние интерфейсы администратора и провайдера. При необходимости откатить версию приложения; новые колонки и данные сохраняются. Автоматического DROP или восстановления всего бэкапа поверх текущих данных нет.

## Контракты и ограничения

- Дополнительные поля API: `middleName`, `noHigherEducation`, `currentCompany`, `previousCompanies`; `studentProfileEnabled` возвращается для каждого ученика через PostgreSQL-адаптер.
- Компании с галочкой попадают в `current_company`, остальные — в `previous_companies`; значения разделяются запятыми. Пустые списки очищаются до NULL. `stop_list_company` содержит общий список. Отсутствующий ключ в частичном обновлении не очищает колонку.
- Сохранение прежних полей и дополнительных полей остаётся последовательным. Ошибка второй записи может означать, что первая уже сохранена; интерфейс показывает ошибку и сохраняет ввод. Общая транзакция сохранения профиля и новая серверная бизнес-валидация не добавлены.
- Изменения подписей, Username, оформления, строгого ввода и модального окна доступны всем ученикам. Сохраняется загрузка паролей отдельным защищённым запросом из текущего master; до успешной загрузки сохранение заблокировано. Статусы Dolphin и Telegram загружаются как в прежнем рабочем кабинете.
- Подсказка желаемой локации упоминает `; ` по согласованному тексту. Существующая проверка пока принимает один `City, Country` либо `Remote`; поддержку нескольких локаций это изменение не добавляет.

```text

```

Для браузерного сценария выполнить `npm run web:build`, затем `npm run web:student-profile:e2e`. Флаги сборки не требуются. Тест запускает только локальный сервер статических файлов и Chromium с подставным API; БД, backend, Telegram и внешние сервисы не запускаются. Скриншоты сохраняются в `tmp/student-profile-e2e/`.

Проверены desktop 1440 px и mobile 390 px, общий редактор профиля и мест работы, восстановление галочек, ошибки, Username, телефоны, подсказки, Escape/отмена, блокировка повторного сохранения и загрузка паролей. Новый кабинет проверяется у двух учеников с разными ID/email, с сохранением данных каждого отдельно; интерфейсы администратора и провайдера остаются прежними. На восстановленной SQL-базе проверены перенос компаний, NULL, частичное обновление и создание/редактирование/удаление `phone_ru` с ID, отличающимся от рабочего.

Миграция проверена повторным запуском, сравнением отпечатков всех прежних строк, отказом при несовместимой колонке/дубле платформы и откатом по таймауту блокировки. Эти проверки выполнялись на локальном восстановлении, не на рабочих профилях.
